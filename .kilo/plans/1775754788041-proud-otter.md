# Plan: Speed Up "Generate Updates" Functionality

## Problem Analysis

The "Generate updates" feature in `backend/app/api/routes/markets.py:81-164` is slow because:

1. **Full history fetch every time** (line 98): Fetches the ENTIRE price history from Polymarket CLOB API on each call - no caching
2. **Sequential inserts** (lines 104-121): Inserts each snapshot individually in a loop
3. **Sequential LLM calls** (line 156): Each update article generation waits for the previous to complete

The threshold for significant moves is 10pp (line 24: `THRESHOLD = 0.10`).

## Proposed Optimizations

### 1. Cache Price History (High Impact)
- Store fetched price history in the database or cache
- On subsequent calls, only fetch new data since last snapshot
- Change `fetch_price_history` to accept `since` parameter

### 2. Batch Database Inserts (Medium Impact)
- Replace individual `pg_insert` calls in a loop with bulk insert
- Use `execute_many` or batch the inserts

### 3. Parallel LLM Calls (High Impact)
- Use `asyncio.gather()` to generate multiple update articles concurrently
- Currently sequential at line 156: `article_data = await _llm.generate_update(market, prev, curr)`

### 4. Incremental Processing (Medium Impact)
- Track last processed date per market
- Only process new snapshots since last run
- Skip re-fetching history if already up-to-date

## Implementation Steps

1. **Modify `polymarket.py`**: Add `since` parameter to `fetch_price_history()` to fetch only new data
2. **Modify `markets.py`**: 
   - Track last snapshot date per market
   - Only fetch new data if stale
   - Use batch inserts for snapshots
   - Use `asyncio.gather()` for parallel LLM calls

## Tradeoffs

- **Parallel LLM calls**: Will implement with semaphore to limit concurrency (e.g., max 5 concurrent calls)
- **Caching complexity**: Need to handle cache invalidation if API data changes

## Implementation Plan

1. **Modify `polymarket.py`**: Add `since` parameter to `fetch_price_history()` to fetch only new data
2. **Modify `markets.py`**:
   - Track last snapshot date per market (query max date from MarketSnapshot)
   - Only fetch new data if stale (add conditional)
   - Use batch inserts for snapshots (collect all values then execute once)
   - Use `asyncio.gather()` with semaphore for parallel LLM calls (max 5 concurrent)
